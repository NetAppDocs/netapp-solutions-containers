= Back up and restore container applications in a vSphere Kubernetes Service cluster using NetApp Console
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ../media/

[.lead]
Back up and restore container applications in a vSphere Kubernetes Service (VKS) cluster using NetApp Console. This procedure covers creating and managing backup and restore operations through Backup and Recovery Service via NetApp Console, using ONTAP S3 object storage as the backup target.

NetApp Console provides centralized management of storage and data services across on-premises and cloud environments. It delivers unified control, operational simplicity, and secure management. There are several data services and management features that can be accessed from the user interface at link:https://console.netapp.com[console.netapp.com^]. For complete details about NetApp Console, see link:https://docs.netapp.com/us-en/console-family/[NetApp Console documentation].

This section focuses on the NetApp Backup and Recovery data service for Kubernetes workloads, specifically container applications on vSphere Kubernetes Service clusters. NetApp Backup and Recovery Service enables you to discover, manage, create, and associate protection policies with your Kubernetes applications using a single interface. For a complete guide, see link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html[NetApp Backup and Recovery documentation].

== Backup and Recovery workflow
. *Ensure you have a Console agent*
+
Ensure you have a Console agent deployed in the environment where your VKS cluster is running. For details about installing a Console agent, see the link:https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-on-prem-ova.html#install-a-console-agent-in-your-vcenter-environment[NetApp Console Setup documentation].
+
.Show example
[%collapsible]
====
In NetApp Console, click Deploy Agent as shown in the screenshot, and deploy the agent in the environment where the VKS cluster is running.

In this example, select *On-Premises > With OVA*, copy the OVA URL, and use that URL in vCenter to deploy the Console agent.

Register it using the IP address of the agent in the URL. See link:https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-on-prem-ova.html[the documentation] for detailed instructions. After the agent is registered, you can see it in NetApp Console as shown in the screenshot below.

. *Set up ONTAP S3 as a backup target*
+
In this example, we use ONTAP S3 Object Storage as the backup target. You can also use AWS S3, Azure Blob, Google Cloud Storage or StorageGRID as backup targets.
+
For additional details, review link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-setup.html#prepare-the-backup-destination[NetApp Console documentation].
+
To discover ONTAP S3 Object Storage as the backup target in NetApp Console, you will need the following information from your ONTAP cluster.
+
----
S3 Endpoint:
Access Key:
Secret Key:
Bucket Name:
----
+
To get these values, do the following in your ONTAP cluster using the System Manager.
+
[loweralpha]
.. Create an S3-enabled SVM in the ONTAP cluster to store the backup data. Note the S3 endpoint URL for this SVM.

.. In the S3 settings of the SVM, create a user and assign the required access. Note the access key and secret key for this user.
+
NOTE: Trident Protect requires the S3 user to have at least `PutObject`, `GetObject`, `ListBucket`, and `DeleteObject` permissions. Without these permissions, AppVault backup and restore operations fail with access-denied errors. For details, see link:https://docs.netapp.com/us-en/trident/trident-protect/trident-protect-appvault-custom-resources.html#s3-compatible-storage-iam-permissions[Trident Protect AppVault documentation].
+
.Show example

. *In NetApp Console, discover the vSphere Kubernetes cluster*
+
.Show example
[%collapsible]
====
This step requires the vSphere Kubernetes cluster to be running and the Console agent to be deployed in the same environment.
Follow these steps to discover the vSphere Kubernetes cluster in NetApp Console.

. In NetApp Console, select *Inventory > Kubernetes* and provide the details of the vSphere Kubernetes cluster.
. Select the agent deployed in the same environment where the vSphere Kubernetes cluster is located.
. Copy the provided commands to install Trident Protect and run them from a machine that is connected to your vSphere Kubernetes cluster.
. After Trident Protect is successfully installed, click *Discover*. NetApp Console discovers the vSphere Kubernetes cluster and all its resources via the agent and populates them in the UI.

. *In NetApp Console, create an application for the container workloads and protect it using backups*
+
NOTE: You need the Backup and Recovery super admin or Backup and Recovery backup admin role to create and protect a Kubernetes application.
+
.Show example
[%collapsible]
====
In this step, create an application in NetApp Console for the container applications in your vSphere Kubernetes cluster that need to be protected. You can use namespaces to create an application to protect all the container applications in a namespace in the vSphere Kubernetes cluster.

You will also need a protection policy to associate with the application. You can create a new protection policy or use an existing one.

image::vks-console-br-011.png[Create application for container applications]

Provide application details and define criteria for the application. In this example, the application is created for all container applications in a namespace in the vSphere Kubernetes cluster. Click *Search* to see the list of namespace-scoped resources that are part of the application. Click *Next* to proceed.

image::vks-console-br-012.png[Provide application details and define criteria for the application]

Next, you need to provide the protection settings for the application. You can create a new protection policy or use an existing one. In this example, a new protection policy is created for the application and associated with it. Expand *Policy* and click *Create new policy*.

image::vks-console-br-013.png[Create new protection policy]

Provide a name for the policy and choose the backup architecture. In this example, disk to object storage is chosen. Define the local snapshot schedule, which controls how often snapshots are taken on the primary storage. Then configure the object storage backup settings separately: choose the backup target (in this example, ONTAP S3), set the transfer schedule that controls when snapshot data is copied to object storage, and specify the number of retention copies. The transfer schedule is independent of the snapshot schedule, so resources are copied to object storage according to the transfer schedule, not immediately when each snapshot is taken. You can also modify the maximum retries and retry interval if you need to. Click *Create* to proceed. The application will be discovered and the protection policy will be associated with it.

image::vks-console-br-015.png[Select backup architecture]

image::vks-console-br-016.png[Local snapshot schedule]

. *Restore the application from a backup*
+
.Show example
[%collapsible]
====
* You can choose any available restore point — a local snapshot, an object storage backup, or a backup from a secondary target — to restore the application.
* You can restore the application to its original namespace or to a different namespace.
* You can select which resources to include in the restore.
* You can choose the storage class to use for the restored application resources.

image::vks-console-br-019.png[Restore application from backup]

image::vks-console-br-020.png[Choose a restore point]

image::vks-console-br-021.png[Select restore options]

image::vks-console-br-022.png[Select all or some resources to restore]

image::vks-console-br-023.png[Select storage class for restored resources]

You can watch the progress of the restore job in the Monitor section of NetApp Console. After the restore job is completed, you can see the restored resources in the vSphere Kubernetes cluster.
